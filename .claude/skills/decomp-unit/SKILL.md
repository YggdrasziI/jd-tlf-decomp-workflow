# decomp-unit

Method for one unit of `NPUG80330` (`LEVELSTARTUP_DISC.PRX`). Acceptance criteria and
naming are in `SPEC.md`; the PRX format and build pipeline in `notes/PRX.md`; compiler
idioms that fix near-misses in `notes/MATCHING.md`. splat options:
`E:\Projets\Github\Decomp\Tools\PSP\splat\docs\{Configuration,Segments}.md`.

Prerequisite: the compiler is identified (`notes/COMPILER.md`). Until then only
splitting and naming work is possible.

## 1. Bounds

- Anchors: source-path strings (`notes/SPLITS.md`) and the functions that use them,
  call clusters (functions called only from one region), string runs in `.rodata` in
  source order, alignment padding, C++ class layout (vtables in `.data`, their
  methods). A bound found this way is a hypothesis until the unit matches; say so in
  the header comment and in `notes/SPLITS.md`.
- Assembly: `asm/NPUG80330/levelstartup/` (generated by `python tools/configure.py`);
  Ghidra (`notes/GHIDRA.md`) helps read the code, it proves nothing.

## 2. Data

For each symbol the code uses, find its users (`grep` the assembly; relocation
tables through `tools/prx.py`). A data range belongs to the unit when only this unit
uses it and it sits between the neighbours' ranges. Typical sections: `.text`,
`.rodata` (strings, float constants, jump tables), `.data` (vtables, tables), `.bss`,
`.sdata`/`.sbss` (`$gp`-relative).

## 3. Split and symbols

- Add the unit to `config/NPUG80330/splat.levelstartup.yaml` in address order
  (`[0x<file offset>, c, <path>]` for code, matching `rodata`/`data` subsegments);
  file offset = vram + 0x74 in program header 0.
- Rename symbols in `config/NPUG80330/symbol_addrs.txt` only with evidence; otherwise
  keep `func_<addr>` / `D_<addr>`. Explain every change in the commit.
- `python tools/configure.py` (reruns splat), then `ninja`: still matching, every
  function is `INCLUDE_ASM`.

## 4. Write and compare

- Header comment: unit range, how the bounds were found, real file name if proven.
- Reuse shared headers (`include/`) and types already named; declare not yet
  decompiled functions `extern` with their splat names.
- First draft: m2c (command in `SPEC.md`, on the `.vfpu.s` copy); never keep its
  output unchecked. Compile with SNC `-O2 -g` (`notes/COMPILER.md`).
- `ninja`, then compare with objdiff (GUI or `python tools/asm_compare.py`, step 3).
- Iterate on: statement and declaration order, local variables vs re-reads, `const`,
  early return vs fall-through, inline helpers, types and signedness, loop forms.
  When stuck, look the symptom up in `notes/MATCHING.md`.
- VFPU functions stay `INCLUDE_ASM` until the compiler's VFPU support is known.
- For many variants, script them in the session scratchpad and read the score from
  the report; check that the compile succeeded before reading a score.

## 5. Finish

- 100 % for every function and data: remove the `INCLUDE_ASM`s, run `ninja` and check
  `LEVELSTARTUP_DISC.PRX: OK`. A per-file compiler or flag needs a justification in
  the unit's header comment and in `notes/MATCHING.md` or `notes/COMPILER.md`.
- Otherwise keep `INCLUDE_ASM` for the unfinished functions, with a comment giving the
  percentage and the remaining difference.
- Add or update the unit's row in `notes/SPLITS.md` (bounds, content, status).
- Then run the `unit-readiness` skill.
